# SimpleGoTo 요구사항과 설계

2026-11-24 사용자 요구로 다시 정했습니다. 이 문서가 기능 범위의 기준입니다. 할 일의 순서와 진행 상황은 [ROADMAP.md](ROADMAP.md)에 있습니다.

- 요구사항: `REQ-<영역>-<번호>`. 무엇이 되어야 하는지.
- 설계: `DES-<영역>-<번호>`. 어떻게 할지. 각 설계에는 근거 요구사항을 적습니다.
- 영역: SYS 시스템, LOC 위치·시각, ATT 자세, MAG 지자기, AST 천체 계산, PNT 지향, TRK 추적, MOT 모터, PA 극축 정렬, CFG 설정, CAL 보정, UI 화면.
- 상태: **있음** 지금 코드에 있음, **일부** 일부만 있거나 바꿔야 함, **없음** 새로 만들어야 함.

---

## 1. 목적과 범위

**수동 적도의식 망원경을 자동화**합니다. 사람은 경통을 손으로 대상에 맞추고, SimpleGoTo는 경통이 하늘의 어디를 가리키는지와 대상까지 얼마나 남았는지 알려 줍니다. 대상에 맞춘 뒤에는 RA 축 모터 하나로 추적합니다.

- 자동으로 대상까지 돌아가는 동작(두 축 slew)은 하지 않습니다. 그래서 Dec 축 모터는 없습니다.
- 이름의 "GoTo"는 **안내를 받아 손으로 찾아가는 것**을 뜻합니다.

## 2. 요구사항

| **REQ-SYS-02** | OLED와 로터리 엔코더 하나로 모든 기능을 조작합니다. 폰 원격 UI(선택 빌드)로도 같은 조작을 합니다. | 있음 |

| **REQ-LOC-03** | 직전에 GPS로 얻은 위치를 저장해 두었다가, GPS fix가 없을 때 씁니다. | 있음 (v0.2.0) |

| **REQ-PNT-01** | 위치, 자세, 방위, 천체 계산으로 경통이 지금 하늘의 어디(RA/Dec, 고도/방위)를 가리키는지 보여 줍니다. | 일부 (중력 방식 B만. 방위를 쓰는 방식 A는 지자기 뒤) |
| **REQ-PNT-02** | 고른 대상과 지금 지향의 차이를 보여 주어, 손으로 대상을 찾아가게 합니다. | 있음 (v0.2.0, dRA/dDEC, ON TARGET) |
| **REQ-TRK-01** | 대상에 맞춘 뒤 추적 기능을 켜면, 그 대상을 따라가도록 모터를 돌립니다. | 있음 (개루프) |
| **REQ-MOT-01** | 모터를 지구 자전 속도(항성시, 15.041″/s)에 맞춰 돌립니다. | 있음 (속도 보정값 RAduty는 실물에서 찾아 저장) |
| **REQ-MOT-02** | 모터를 달의 겉보기 운동 속도(달 추적 속도)에 맞춰 돌립니다. | 있음 |
| **REQ-PA-01** | 극축 정렬을 보조합니다. | 일부 (고도와 북극성 위치. 방위는 지자기 뒤) |
| **REQ-CFG-01** | 설정을 내부 메모리에 저장하고, 다시 켜면 불러옵니다. | 있음 |
| **REQ-CAL-01** | 자이로 보정: 시작을 누르면 모든 모터를 멈추고 약 30초 동안 자이로 값의 이동평균을 구합니다. 끝나면 그 값(자이로 바이어스)을 보여 주고 적용할지 묻습니다. 적용하면 자세 추정 등의 연산에 바이어스를 뺀 자이로 값을 씁니다. | 있음 (v0.2.0) |
| **REQ-CAL-02** | 가속도 보정: 3축의 +/− 방향(X+, X−, Y+, Y−, Z+, Z−) 각각에서 가속도의 이동평균을 측정해 보정값을 구합니다. | 있음 (v0.2.0) |
| **REQ-CAL-03** | 보정값을 얻는 동안 충격 등이 감지되면 보정 실패를 표시하고, 다시 보정하도록 안내합니다. | 있음 (v0.2.0) |

## 3. 설계

### 3.1 시스템 (SYS)

| ID | 설계 | 근거 |
|---|---|---|
| **DES-SYS-01** | 하드웨어는 지금 구성을 유지합니다: NodeMCU v3(ESP8266), ICM20948(가속도·자이로·지자기), GPS, SSD1306, 로터리, H-브리지 + RA DC 모터 1개. 추가 핀은 쓰지 않습니다(전압 측정용 A0 제외). | REQ-SYS-01 |
| **DES-SYS-02** | **모터 정지 요청**을 한 곳에 둡니다: `UiState.motor_inhibit`. 보정 화면과 극축 정렬 화면이 켜고, `applyTracking()`과 RA Speed 화면은 이 값이 켜져 있으면 PWM 0을 냅니다. 화면을 나가면 끄고, 추적은 그 전 상태로 돌아갑니다. | REQ-CAL-01, REQ-CAL-02, REQ-PA-01 |
| **DES-SYS-03** | 새 계산(보정, 설정 직렬화, 지향 계산)은 하드웨어와 떨어진 순수 C++로 만들어 PC 단위 테스트와 UI 시뮬레이터에서 검증합니다(지금 `src/astro`, `src/ui`와 같은 방식). | 전체 |

### 3.2 위치와 시각 (LOC)

| ID | 설계 | 근거 |
|---|---|---|
| **DES-LOC-01** | **위치 출처**는 설정 `location_mode`로 고릅니다. `Auto`: GPS fix → 직전 GPS 값 → 수동 값 순서로 씁니다. `Manual`: GPS가 있어도 수동 값만 씁니다. 3Status > GPS 화면에 지금 쓰는 출처(`SRC GPS` / `LAST` / `MAN`)를 표시합니다. | REQ-LOC-01~03 |
| **DES-LOC-02** | **직전 GPS 값 저장**: fix(품질 > 0, 위성 4개 이상)가 30초 이상 유지되면, 저장된 값이 없거나 저장 위치에서 1 km 넘게 벗어났을 때 위도·경도·고도와 그 날짜를 저장합니다. 전원을 켤 때마다 최대 한 번 쓰므로 플래시 수명에 문제가 없습니다. | REQ-LOC-03, REQ-CFG-01 |
| **DES-LOC-03** | **수동 위치 입력 화면**: 위도(±DD.DDDD), 경도(±DDD.DDDD), 고도(m)를 로터리로 고칩니다. 클릭으로 고칠 자리를 옮기고(10°, 1°, 0.1°, 0.01°, 0.0001°), 마지막 `Save`로 저장합니다. | REQ-LOC-02 |
| **DES-LOC-04** | **시각**: GPS가 없으면 UTC 날짜·시각을 손으로 넣습니다. 넣은 뒤에는 `millis()`로 흘러갑니다. 전원을 끄면 의미가 없으므로 시각은 저장하지 않습니다. 대신 지역 시간대(UTC 오프셋, 예: +9)는 설정으로 저장해 화면 입력을 지역 시각으로 받을 수 있게 합니다. 상태바 시각 앞 글자를 `T`(GPS) / `M`(수동)으로 바꿔 출처를 표시합니다. | REQ-LOC-02 |
| **DES-LOC-05** | (선택) 원격 UI가 켜져 있으면 폰 페이지가 접속할 때 폰 시각을 보내고, GPS가 없을 때 그 시각을 씁니다. | REQ-LOC-02 |

### 3.3 자세 (ATT)

| ID | 설계 | 근거 |
|---|---|---|
| **DES-ATT-01** | 자세 추정기는 보정된 가속도(DES-CAL-05)와 보정된 자이로(DES-CAL-03)를 받습니다. Roll/Pitch는 지금의 상보필터(τ = 1 s)를 그대로 씁니다. | REQ-ATT-01 |
| **DES-ATT-02** | Yaw(방위)는 기울기 보정한 지자기 방위(DES-MAG-03)와 자이로 적분을 같은 상보필터로 합칩니다. 지자기만 쓰는 것보다 흔들림이 적습니다. | REQ-ATT-01, REQ-MAG-01 |
| **DES-ATT-03** | 7 Att.Estimator 화면에 Yaw를 추가합니다. 칼만 필터(R/Q/K)로 바꾸는 것은 실물 잡음을 본 뒤 정합니다. | REQ-ATT-01 |

### 3.4 지자기와 방위각 (MAG)

| ID | 설계 | 근거 |
|---|---|---|
| **DES-MAG-01** | **지자기 보정(hard/soft iron)**: 보정 화면에서 경통(또는 센서)을 여러 방향으로 30~60초 돌리는 동안 축별 최솟값·최댓값을 모읍니다. 오프셋 = (max + min) / 2, 축 배율 = 평균 반지름 / 축 반지름. 적용할지 묻고 저장합니다. 측정 중에는 모터를 멈춥니다(DES-SYS-02). 한 축이라도 범위가 너무 작으면 "더 돌리세요"를 표시하고 끝내지 않습니다. | REQ-MAG-01 |
| **DES-MAG-02** | **자편각**: 진북과 자북의 차이를 설정 `declination_deg`(동편 +)로 저장합니다. 기본값은 0이고 극축 정렬 화면에서 0이면 입력하라고 안내합니다. 예를 들어 한국은 서편각 약 8~9°이며, 정확한 값은 지자기 모델 서비스에서 확인해 넣습니다. | REQ-MAG-01, REQ-PA-01 |
| **DES-MAG-03** | **방위각 계산**: 보정된 지자기 벡터를 Roll/Pitch로 수평면에 투영(기울기 보정 나침반)해 자북 방위를 구하고, 자편각을 더해 진북 방위로 바꿉니다. 경통 광축(`IMU_TUBE_OPTICAL_AXIS`)의 방위로 표시합니다. 3Status > Mag/Temp 화면에 보여 줍니다. | REQ-MAG-01 |
| **DES-MAG-04** | **간섭**: 모터 전류와 Wi-Fi 송신이 지자기에 영향을 줄 수 있습니다. 추적 중에는 방위값 옆에 `*`를 붙여 정확도가 떨어질 수 있음을 알립니다. 극축 정렬은 모터를 멈추고 합니다. 실물에서 차이를 측정합니다. | REQ-MAG-01, REQ-PA-01 |

### 3.5 천체 계산 (AST)

| ID | 설계 | 근거 |
|---|---|---|
| **DES-AST-01** | 지금의 `src/astro`(달, 수성~해왕성, 관측지 보정, 추적 속도)를 그대로 씁니다. 위치와 시각은 DES-LOC-01의 출처에서 받습니다. GPS fix 여부가 아니라 "위치와 시각이 있는가"로 계산을 켭니다. | REQ-AST-01, REQ-LOC-02 |
| **DES-AST-02** | 극축 정렬을 위해 북극성(작은곰자리 α)의 RA/Dec를 상수로 넣고 세차 보정을 해서 시간각을 계산합니다(DES-PA-03). | REQ-PA-01 |

### 3.6 지향과 안내 (PNT)

| ID | 설계 | 근거 |
|---|---|---|
| **DES-PNT-01** | **방법 A, 고도/방위**: 경통 광축의 고도(중력)와 진북 방위(DES-MAG-03)로 Alt/Az를 구하고, 관측지 위도와 지방항성시로 RA/Dec로 바꿉니다. 극축 정렬과 상관없이 쓸 수 있지만 지자기 정확도(대략 1~3°)에 묶입니다. | REQ-PNT-01, REQ-MAG-01 |
| **DES-PNT-02** | **방법 B, 가대 좌표**: 지금 구현(`pointingFromUp`, 중력 방향만으로 시간각/적위, 대상 쪽으로 대칭 모호성 해소)입니다. 극축이 정렬되어 있으면 지자기가 필요 없고 더 정확합니다. | REQ-PNT-01 |
| **DES-PNT-03** | **고르는 규칙**: 극축 정렬 화면에서 정렬 완료를 확인하면(DES-PA-04) B를 쓰고, 아니면 A를 씁니다. 두 값의 차이가 크면(예: 5° 이상) 정렬이 틀어졌다고 표시합니다. | REQ-PNT-01, REQ-PA-01 |
| **DES-PNT-04** | **안내 표시**: 대상 화면에 `dRA`(시간각 방향, 분 단위), `dDEC`(°)와 돌릴 방향(`E`/`W`, `N`/`S`)을 보여 줍니다. 둘 다 허용 범위(설정, 기본 1°) 안이면 `ON TARGET`을 표시하고 추적을 켜라고 안내합니다. | REQ-PNT-02 |

### 3.7 추적과 모터 (TRK, MOT)

| ID | 설계 | 근거 |
|---|---|---|
| **DES-TRK-01** | **추적 방식**은 두 가지입니다: `Sidereal`(항성시 15.041″/s), `Lunar`(달 추적 속도, `src/astro`가 1초마다 계산하는 관측지 기준 RA 속도). 대상이 달이면 `Lunar`, 행성과 그 밖은 `Sidereal`이 기본이고 화면에서 바꿀 수 있습니다. | REQ-TRK-01, REQ-MOT-01, REQ-MOT-02 |
| **DES-TRK-02** | 대상을 고르는 일(지향 안내)과 추적 속도를 고르는 일을 나눕니다. 추적은 지금 경통이 가리키는 곳을 그 속도로 따라갑니다. 행성의 고유 운동은 관측 시간 동안 무시할 만큼 작아서 항성시로 충분합니다. | REQ-TRK-01 |
| **DES-MOT-01** | **모터 지령** = `RA_DUTY_AT_SIDEREAL × 속도 / 15.041 + Offset`(개루프). `RA_DUTY_AT_SIDEREAL`은 빌드 상수에서 **설정값**으로 옮기고, RA Speed 화면에서 별을 따라가며 찾은 RRcmd를 Settings 화면의 `RAduty = RRcmd`로 저장합니다. | REQ-MOT-01, REQ-CFG-01 |
| **DES-MOT-02** | **반구**: 위도가 음수(남반구)이면 모터 방향을 반대로 합니다. 설정 `motor_reverse`로 배선 방향도 바꿀 수 있게 합니다. | REQ-MOT-01 |
| **DES-MOT-03** | (나중) 추적 중 지향(방법 B)의 RA가 천천히 벗어나는 만큼 PWM을 고치는 느린 보정 루프. 개루프 결과를 실물에서 본 뒤 정합니다. | REQ-TRK-01 |

### 3.8 극축 정렬 보조 (PA)

| ID | 설계 | 근거 |
|---|---|---|
| **DES-PA-01** | **새 화면 Polar Align**. 들어가면 모터를 멈춥니다(DES-SYS-02). 사용자에게 Dec를 90°(경통을 극축과 나란히, 가대의 기준 자세)로 두라고 안내합니다. | REQ-PA-01 |
| **DES-PA-02** | **고도와 방위 오차**: 경통 광축의 고도와 관측지 위도의 차 `dALT`, 경통 광축의 진북 방위(DES-MAG-03) `dAZ`를 보여 주고, 극축을 움직일 방향(`UP`/`DOWN`, `LEFT`/`RIGHT`)을 표시합니다. 고도는 중력 기준이라 정확하고(0.1° 단위), 방위는 지자기와 자편각 정확도에 묶입니다(DES-MAG-04). | REQ-PA-01 |
| **DES-PA-03** | **정밀 정렬 보조**: 극축 망원경을 쓰는 경우를 위해 북극성의 시간각을 시계 방향 위치(예: `Polaris at 4:30`)로 보여 줍니다(DES-AST-02). 방위 오차가 지자기 한계보다 작아지면 이 방법으로 마무리하라고 안내합니다. | REQ-PA-01 |
| **DES-PA-04** | **정렬 확인**: 두 오차가 허용 범위(기본 고도 0.5°, 방위 2°) 안에서 2초 넘게 유지되면 `OK`를 표시합니다. 사용자가 확인하면 "정렬됨" 표시를 켜고(전원을 끄면 꺼짐), 지향은 방법 B를 씁니다(DES-PNT-03). | REQ-PA-01, REQ-PNT-01 |

### 3.9 설정 저장 (CFG)

| ID | 설계 | 근거 |
|---|---|---|
| **DES-CFG-01** | **저장소**: ESP8266 `EEPROM` 라이브러리(플래시 한 섹터를 흉내 냄)를 씁니다. LittleFS보다 코드가 작고 구조체 하나를 쓰기에 충분합니다. | REQ-CFG-01 |

### 3.10 보정 (CAL)

| ID | 설계 | 근거 |
|---|---|---|
| **DES-CAL-01** | **공통 흐름** (자이로, 가속도, 지자기): `준비`(모터 정지, "가만히 두세요") → `측정`(진행률 표시) → `결과`(값 표시, `Apply` / `Discard`) → `적용·저장` 또는 `실패`(이유 표시, `Retry` / `Quit`). 화면을 나가면 언제든 취소되고 이전 보정값이 그대로 남습니다. | REQ-CAL-01~03 |
| **DES-CAL-02** | **충격 감지**: 측정 중 샘플마다 본다. ① 자이로 크기 \|ω\|가 그때까지의 평균에서 2 °/s 넘게 벗어남, ② 가속도 크기 \|a\|가 그때까지의 평균에서 0.5 m/s² 넘게 벗어남. 하나라도 걸리면 그 측정을 버리고 `Shock detected. Retry`를 표시합니다. 시작 직후 1초는 버튼을 누른 손 떨림이 섞이므로 판정과 평균에서 뺍니다. 문턱값은 `board_config.h` 상수로 두고 실물에서 조정합니다. | REQ-CAL-03 |
| **DES-CAL-03** | **자이로 보정**: 시작을 누르면 모터 정지(DES-SYS-02) → 1초 안정 대기 → 30초 동안(10 Hz, 300개) 축별 누적 이동평균과 표준편차를 구합니다. 진행 `12/30 s`를 표시합니다. 끝나면 바이어스 X/Y/Z(°/s)와 표준편차를 보여 주고 `Apply?`를 묻습니다. `Apply`: `UiState.gyro_bias`에 넣어 자세 추정에 바이어스를 뺀 값을 쓰고 설정에 저장합니다. `Discard`: 이전 값을 유지합니다. 지금의 16초 3단계 보정기(`bias_calibrator.h`)는 이것으로 바꿉니다. | REQ-CAL-01, REQ-CAL-03 |
| **DES-CAL-04** | **가속도 6방향 측정**: 순서대로 `X+ up`, `X- up`, `Y+ up`, `Y- up`, `Z+ up`, `Z- up`을 안내합니다. 각 단계에서 ① 해당 축이 0.8 g 넘게 그 방향을 향하고 나머지 축이 작은지 자동으로 확인하고(틀리면 `Turn X+ up`), ② 1초 동안 가만히 있으면 ③ 5초 동안 그 방향의 3축 이동평균을 잽니다. 충격(DES-CAL-02)이 나면 **그 단계만** 다시 합니다. 진행은 `Step 3/6 Y+ up`처럼 표시합니다. | REQ-CAL-02, REQ-CAL-03 |
| **DES-CAL-05** | **가속도 보정값 계산**: 축 i마다 위를 향했을 때 값 p_i, 아래를 향했을 때 값 n_i로 바이어스 b_i = (p_i + n_i) / 2, 배율 s_i = (p_i − n_i) / (2g), g = 9.80665 m/s². 보정 = (a_i − b_i) / s_i. 배율이 0.9~1.1, \|바이어스\|가 1 m/s² 안이 아니면 실패로 보고 다시 하라고 안내합니다. 결과를 보여 주고 `Apply?`를 물은 뒤 적용·저장합니다. 5 Status-IMU Calib 화면에 바이어스와 배율을 보여 줍니다. | REQ-CAL-02 |
| **DES-CAL-06** | **가속도 보정 시 주의**: 경통에 붙은 채로는 6방향을 만들기 어려울 수 있습니다. IMU 모듈(또는 센서 상자)을 떼어 평평한 곳에서 하고 다시 같은 방향으로 붙이라고 문서와 화면 첫 줄에 안내합니다. 축 매핑(`imuSensorToBody`, `IMU_TUBE_*`)은 바뀌지 않습니다. | REQ-CAL-02 |
| **DES-CAL-07** | Gyro Scale 보정과 Acc. Scale 메뉴 항목은 없앱니다. 가속도 배율은 DES-CAL-05에 포함되고, 자이로 배율은 추적 정확도에 영향이 작습니다. | REQ-CAL-01, REQ-CAL-02 |

## 5. 구현 순서 (안)

앞의 것이 뒤의 것의 전제입니다.

1. **설정 저장** DES-CFG-01~06: 보정값과 수동 위치를 담을 곳이 먼저 있어야 합니다.
2. **보정** DES-SYS-02, DES-CAL-01~07: 자이로 → 가속도. 정확한 자세가 지향과 극축 정렬의 바탕입니다.
3. **위치와 시각** DES-LOC-01~04, DES-AST-01: 실내에서도 계산을 시험할 수 있게 됩니다.
4. **지자기와 방위** DES-MAG-01~04, DES-ATT-02~03.
5. **극축 정렬** DES-AST-02, DES-PA-01~04.
6. **지향 안내와 추적 정리** DES-PNT-01~04, DES-TRK-01~02, DES-MOT-01~02.
7. **메뉴 재구성** DES-UI-01. 화면이 다 생긴 뒤 한 번에 바꿉니다.
8. (나중) DES-MOT-03 닫힌 루프 추적, DES-LOC-05 폰 시각.

각 단계는 PC 테스트와 시뮬레이터로 먼저 확인하고, 문턱값(DES-CAL-02, DES-PA-04)과 정확도는 실물에서 조정합니다.

# 달·행성 위치 계산 정리

`9 Axis for Moon` 기능을 위해 GPS 시각과 위치로 달의 적경(RA)과 적위(Dec)를 구하는 방법을 정리한 문서입니다. `reference/`의 MATLAB 코드를 검토한 결과와 조사한 자료를 함께 담았습니다.

---

## 1. reference/trackingPlanet.m 검토

`trans`와 `planetary_properties`가 파일 안으로 들어와 `libs` 폴더 없이도 실행할 수 있게 되었습니다. 궤도요소와 변화율(J2000 기준, 각도 변화율은 arcsec/세기)과 단위 변환(`trans`), 궤도면 → 황도 좌표 회전 행렬 `QxX`는 맞습니다.

### 1.1 고친 점

1–3번은 2026-11-22에 `reference/trackingPlanet.m`에 반영했습니다. 4–5번은 선택 사항이라 그대로 두었습니다.

| # | 위치 | 문제 | 수정 |
|---|---|---|---|
| 1 | `theta = 2 * atan(sqrt((1-e)/(1+e))*tand(E/2))` | **진근점이각 공식에서 (1+e)와 (1-e)가 바뀌었습니다.** 올바른 식은 tan(θ/2) = √((1+e)/(1−e))·tan(E/2) 입니다. `trackingMoon.m`에는 올바르게 되어 있습니다. | `sqrt((1+e)/(1-e))` |
| 2 | `vx = (h/mu) * [...]` | 속도 크기 계수가 뒤집혔습니다. 올바른 식은 (μ/h)·[−sinθ, e+cosθ, 0] 입니다. 그림에는 쓰이지 않아 결과에는 영향이 없습니다. | `(mu/h) * [...]` |
| 3 | `try tmp = planet.circle(1,1); catch ... planet_out.circle = ...` | catch에서 `planet_out.circle`을 만든 뒤 아래에서 `planet_out = planet;`으로 덮어써서 궤도 원이 저장되지 않습니다. 그러면 그리기 단계의 `%s.circle(1,:)`에서 필드가 없다는 오류가 납니다. | catch 안에서 `planet.circle = QxX * circle';`로 저장 |
| 4 | 파일 첫 구간 | 현재 시각으로 JD를 계산하지만 이후에 쓰지 않고, `addpath('libs')`도 더 이상 필요 없습니다. | 정리(선택) |
| 5 | 이중 `for i` | 바깥 루프와 안쪽 루프가 같은 변수 `i`를 씁니다. MATLAB에서는 동작하지만 읽기 헷갈립니다. | 안쪽을 `k`로(선택) |

**1번 오차 크기 (Python으로 같은 식을 옮겨 한 궤도 동안 비교)**

| 행성 | 이심률 e | 태양 중심 황경 최대 오차 |
|---|---|---|
| 지구 | 0.0167 | 1.91° |
| 화성 | 0.0934 | 10.72° |
| 수성 | 0.2056 | 약 24° (≈ 2e rad로 추정) |

근일점·원일점 근처에서는 오차가 작아서 눈에 잘 띄지 않습니다. 예를 들어 화성이 근일점 근처였던 2003-08-27 12:00 UT에는 지구–화성 거리가 현재 식 0.3735 AU, 수정 식 0.3729 AU로 거의 같습니다. 실제값은 0.3727 AU입니다.

### 1.2 망원경에 쓰려면 더 필요한 것

이 스크립트가 구하는 것은 **태양 중심 황도 좌표**입니다. 행성의 적경·적위를 얻으려면 다음 과정이 더 필요합니다.

1. 지구 중심 벡터 = 행성 위치 − 지구 위치
2. 황도경사 ε(≈ 23.4393°)로 x축 회전 → 적도 좌표
3. RA = atan2(y, x), Dec = atan2(z, √(x²+y²))

## 2. reference/trackingMoon.m 검토

달 궤도를 이심률이 있는 타원으로 그리는 2체 애니메이션입니다. 쓰인 상수는 NASA Moon Fact Sheet와 일치합니다(3절 표).

| 항목 | 내용 |
|---|---|
| 맞는 부분 | 이심률, 각운동량 h, 주기 T 식, 케플러 방정식, 진근점이각 식 |
| 실행 오류 | `warp_2pi` 함수가 파일 안에 없습니다(`trackingPlanet.m`에는 `warp_360`만 있음). |

→ 달의 실제 적경·적위는 4절의 방법으로 구해야 합니다.

## 4. 달 위치 계산 방법 (저정밀, ESP8266용)

출처: Paul Schlyter, [How to compute planetary positions](https://stjarnhimlen.se/comp/ppcomp.html). 정확도는 달 1–2′(각분)이고, 부동소수 sin/cos 몇십 번이면 계산됩니다.

### 4.1 시간

GPS의 UTC 날짜·시각(y, m, D, UT[시간])으로 2000-01-00.0 UT 기준 일수 d를 구합니다(1900-03 ~ 2100-02 유효, 나눗셈은 모두 정수 나눗셈).

```
d = 367*y - 7*(y + (m+9)/12)/4 + 275*m/9 + D - 730530 + UT/24.0
```

JD로는 `JD = d + 2451543.5` 입니다.

### 4.2 궤도요소 (각도 단위는 °, d는 일)

| | 달 | 태양 |
|---|---|---|
| N (승교점 황경) | 125.1228 − 0.0529538083·d | 0 |
| i (궤도경사) | 5.1454 | 0 |
| w (근점 인수) | 318.0634 + 0.1643573223·d | 282.9404 + 4.70935e-5·d |
| a (장반경) | 60.2666 지구반지름 | 1.0 AU |
| e (이심률) | 0.054900 | 0.016709 − 1.151e-9·d |
| M (평균근점이각) | 115.3654 + 13.0649929509·d | 356.0470 + 0.9856002585·d |

황도경사: `ecl = 23.4393 − 3.563e-7·d`

**변화율에서 계산한 주기** (팩트시트에는 없는 값)

| 주기 | 값 | 계산 |
|---|---|---|
| 근점월 | 27.5545 일 | 360 / 13.0649929509 |
| 승교점 역행 주기 | 6798 일 ≈ 18.61 년 | 360 / 0.0529538083 |
| 근지점 세차 주기 | 3231 일 ≈ 8.85 년 | 360 / (0.1643573223 − 0.0529538083) |

### 4.3 계산 순서

1. **케플러 방정식:** E − e·sin E = M을 뉴턴법으로 풉니다(라디안, 2~3회면 충분).
2. **궤도면 좌표:** xv = a(cos E − e), yv = a√(1−e²)·sin E, v = atan2(yv, xv), r = √(xv² + yv²)
3. **지구 중심 황도 좌표:**
   - xh = r(cos N·cos(v+w) − sin N·sin(v+w)·cos i)
   - yh = r(sin N·cos(v+w) + cos N·sin(v+w)·cos i)
   - zh = r·sin(v+w)·sin i
   - 황경 = atan2(yh, xh), 황위 = atan2(zh, √(xh² + yh²))
4. **섭동 보정** (태양의 영향). 먼저 Ls = Ms + ws, Lm = Mm + wm + Nm, D = Lm − Ls, F = Lm − Nm 을 구합니다.
   - 황경 [°]:
     - −1.274·sin(Mm−2D) (출차, Evection)
     - +0.658·sin(2D) (이차, Variation)
     - −0.186·sin(Ms) (연차, Yearly equation)
     - −0.059·sin(2Mm−2D)
     - −0.057·sin(Mm−2D+Ms)
     - +0.053·sin(Mm+2D)
     - +0.046·sin(2D−Ms)
     - +0.041·sin(Mm−Ms)
     - −0.035·sin(D)
     - −0.031·sin(Mm+Ms)
     - −0.015·sin(2F−2D)
     - +0.011·sin(Mm−4D)
   - 황위 [°]:
     - −0.173·sin(F−2D)
     - −0.055·sin(Mm−F−2D)
     - −0.046·sin(Mm+F−2D)
     - +0.033·sin(F+2D)
     - +0.017·sin(2Mm+F)
   - 거리 [지구반지름]:
     - −0.58·cos(Mm−2D)
     - −0.46·cos(2D)
5. **적도 좌표:** 황경·황위·거리로 다시 x, y, z를 만든 뒤 황도경사 ecl만큼 x축으로 회전하고, RA = atan2(ye, xe), Dec = atan2(ze, √(xe² + ye²))를 구합니다.

### 4.4 검증

Meeus, *Astronomical Algorithms* 예제 47.a(1992-04-12 0h)와 비교했습니다. 같은 식을 Python으로 옮겨 계산한 결과입니다.

| | RA | Dec | 거리 |
|---|---|---|---|
| 기준값 (Meeus) | 134.688470° | 13.768368° | 368,409.7 km |
| 섭동 포함 | 134.6659° (−1.4′) | 13.7644° (−0.2′) | 368,082 km (−327 km) |
| 순수 케플러 (섭동 없음) | 136.2457° (+93.4′) | 13.2051° (−33.8′) | 363,381 km (−5,028 km) |

섭동 항을 넣어야 달 지름(약 31′)보다 훨씬 작은 오차가 됩니다.

### 4.5 관측지 보정과 추적 속도

- **시차(parallax):** 달은 가까워서 관측 위치에 따라 지평선 근처에서 약 54–61′(거리 1/r에 비례)까지 달라 보입니다. **달 지름의 거의 두 배이므로 반드시 보정해야 합니다.** mpar = asin(1/r) [r: 지구반지름 단위 거리]
  - topRA = RA − mpar·ρ·cos(gclat)·sin(HA) / cos(Dec)
  - topDec = Dec − mpar·ρ·sin(gclat)·sin(g − Dec) / sin(g), g = atan(tan(gclat) / cos(HA))
  - gclat = lat − 0.1924°·sin(2·lat), ρ = 0.99833 + 0.00167·cos(2·lat)
- **지방항성시(LST):**
  - GMST0 = (Ls + 180°)/15 [시간], Ls = Ms + ws
  - LST = GMST0 + UT + 경도/15
  - 시간각 HA = LST − RA
- **추적 속도:**
  - 별(항성시): 15.041″/s
  - 달: 평균 약 14.49″/s. 달이 하루 약 13.2°씩 동쪽으로 움직여서 별보다 약 3.7% 느립니다.
  - 달의 RA 변화율이 거리와 적위에 따라 달라지므로, 위 계산을 1초 간격으로 두 번 해서 차이로 구하는 편이 정확합니다.

## 5. 펌웨어 구현 (2026-11-22)

모든 내부 계산은 `double`(64비트)입니다. ESP8266에는 FPU가 없어 소프트웨어로 계산하지만, 1초에 한 번만 돌기 때문에 부담이 작습니다. d·변화율 곱(d ≈ 9,800 × 13.06 ≈ 128,000°)도 `double`이면 정밀도 손실이 없습니다.

| 파일 | 내용 |
|---|---|
| `Arduino/app/src/astro/astro.{h,cpp}` | JD, GMST/LST(IAU 1982), 태양·달(Schlyter + 섭동항), 행성(Standish J2000 요소, trackingPlanet.m과 같은 값), 관측지 보정(WGS84 벡터 차), 고도·방위, `moonState()`(±30 s 중앙차분으로 추적 속도 계산) |
| `astro/target_tracker.h` | GPS 날짜 검사(2자리 연도 → 2000+), 대상(달·행성)별로 1 s 주기로만 다시 계산, 대상을 바꾸면 바로 계산, fix가 없으면 무효 |
| `astro/target_telemetry.h` | `Telemetry`의 GPS 값 → 달 값 / 추적 대상 값, 추적 중 RA 모터 지령(`applyTracking`). `app.ino`와 UI 시뮬레이터가 함께 씀 |
| `Arduino/test/test_astro.cpp` | PC 정확도 시험 (아래 표) |
| `Arduino/tools/astro_bench/` | 실측 시험 스케치: 보드에서 같은 예제를 계산해 PC 값과 비교하고, 함수별 실행 시간(µs)을 Serial/OLED로 출력 |

- 에페메리스 시간은 UT + ΔT(69 s, 고정)로 씁니다. ΔT를 빼먹으면 달이 약 38″(0.6′) 어긋납니다.
- 행성은 `planetApparent()`로 광행시간(빛이 오는 동안 행성이 움직인 만큼)과 세차(J2000 → 날짜 기준, Meeus 21.4)를 보정합니다. 장동(최대 약 17″)과 광행차(약 20″)는 넣지 않았습니다.
- Standish 요소 자체의 오차 때문에 목성·토성은 수 분각까지 어긋날 수 있습니다. 저배율 파인더로 찾기에는 충분합니다.
- 화면: `9 Axis for Moon`은 달만, `10 Planet Tracking`은 고른 대상(달, 수성, 금성, 화성, 목성, 토성)을 보여 줍니다. 태양은 망원경 안전 때문에 목록에 넣지 않았습니다.

**남은 일**

- RA 모터 보정: 추적은 `RRcmd = RA_DUTY_AT_SIDEREAL × 추적속도 / 15.041`(개루프, 선형)로 모터 지령을 정합니다. `board_config.h`의 `RA_DUTY_AT_SIDEREAL`이 0이라 아직 모터는 움직이지 않습니다. 1 RA Speed 화면에서 별 하나를 따라가는 RRcmd 값을 찾아 넣어야 합니다. DC 모터는 PWM과 속도가 선형이 아니므로, 필요하면 여러 점을 측정해 표로 바꿉니다.
- Yaw(방위) 추정이 없어 마운트가 달을 향하는지는 아직 판단하지 않습니다.
